## 2. **关键:这是第三种表格朝向**

现有两个解析器都不适用:

| 解析器 | 朝向 | 适用 |
|---|---|---|
| `parse_year_columns` | **年份为列**、指标为行 | 泉州年鉴 1-2 表(如 0102) |
| `parse_plain_series` | **年份为行**、metric 为列 | 泉州年鉴 6-3 表(如 0603) |
| **(缺)** | **地区为行、指标为列** | **福建年鉴各设区市表** |

`0407.htm` 实测网格:

```
行数 17   最大列数 150(畸形 colspan 撑大)
行0: ['4-7 各设区市固定资产投', '', ...]        ← 表题
行1: ['Total Investm', ...]                    ← 英文表题
行2: ['单位：亿元', ...]                        ← 单位行
行3: ['地区', 'Area', '固定资产投资Investm', ...] ← 表头
行4: ['地区', 'Area', '固定资产投资Investm', ...] ← 表头重复(rowspan 展开)
```

⇒ **首列是地区名(福州/厦门/泉州/…),后续各列是不同指标**,而**年份不存在于表内** ——
需由**卷年**提供(注意:福建年鉴 `dz2022` 卷载 **2021** 年数据,即卷年与数据年差 1)。

`parse_yearbook_table(0407)` 返回 **0** —— 两个既有解析器都识别不了该形状,不会"错解",只会空。

## 3. 实现要点(建议做法)

1. 新增 `app/parse/yearbook.py::parse_city_rows(html)` → `[{city, indicator, unit, value}]`
   - 定位表头行(含「地区」/「Area」);
   - 首列数据行 → `city`;其余非空列按**列头文本**作为 `indicator`;
   - 跳过表题行、英文表题行、单位行、`rowspan` 造成的重复表头行;
   - 忽略 colspan 撑出的空列。
2. `app/fetch/yearbook.py` 增加 `ingest_yearbook_cities(...)`,关键差异:
   - `region` 由**行内地区名**决定(而非配置常量);
   - `year` 由**卷年 - 1** 提供,并在 `note` 写明口径;
   - 地区名必须与库内 `bureaus.region` 对齐(福州**市**/厦门**市**…),建议用白名单映射,避免把「全省」也当成地区。
3. 测试:保存真实 `0407.htm` / `0301.htm` 夹具(参考已有 `qz_yearbook_*.htm` 的做法)。
4. 交叉印证:福建年鉴的**各设区市**值与泉州年鉴的**本市**值应对得上,
   可据此校验解析是否正确(这是天然的验收标准)。

## 4. 已验证的相关事实(勿重复踩坑)

- 全角/半角混排、`rowspan` 造成表头重复行,均已在 `_grid` 层面被展开;
- 单位行形如「单位：亿元」,可由 `_global_unit` 读取;
- 国家统计局新版 API **只到省级、不含普通地级市** —— 故地市级只能走年鉴/公报,
  这条已反复确认,不要指望 API 补齐地市。
