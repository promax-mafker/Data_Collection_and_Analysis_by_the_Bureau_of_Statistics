## 1. 问题陈述(全部来自实测,非推测)

| 事实 | 证据 |
|---|---|
| 决策树 7 个 `na` 节点**全部**是时序深度不足,无一因「统计局不公布」 | `tree_audit` 复跑;`missing` 六项全含「序列」二字 |
| 同套代码,宁德采到 **26 个年度公报**、泉州 **0 个** | `pages` 按地区统计 |
| 泉州 0 公报页的原因:走了手工单期旁路 `quanzhou_sources.yaml` | 6 个源 period 全为 2025/2026 |
| 泉州公报栏目实测可回溯 **2007 年**(`index_1..4.htm`) | 本机实测 |
| 泉州年鉴在线版 **2016-2025 连续 10 年**可达 | 本机复核,全部 200 |
| 泉州**不在**国家统计局官方 API 覆盖内(主要城市数据集恰好 36 城,福建仅福州/厦门) | `ALT_SOURCES` §3.1.2 实测枚举 |
| CPI 仅 3/10 地区、固投 5/10、常住人口 4/10 | 真实库覆盖统计 |
| 收入中位数、支出法 GDP(地市)为**真真空** | 对泉州年鉴 2023/2024 两卷全文检索,关键词命中 **0** |

**结论:主因是「我们没采 + 站点适配不完整」,不是数据源不足。**

## 2. 目标与非目标

**目标**
1. 泉州/福建时序深度补齐至 ≥10 年(A 类),解锁决策树 7 个 `na` 节点中的 6 个。
2. 把「已公布但抽取失败」的 CPI / 固投 / 常住人口覆盖提到 ≥8 个地区(B 类)。
3. 接入新版统计局官方 API、CELMA 债务 API、厦门海关分市进出口(C 类 + 地市独立口径)。
4. 建立交叉验证机制,并**显式区分「独立口径」与「同源搬运」**(D 类)。

**非目标(明确不做)**
- 不做全国扩展(仍福建试点)。
- 不引入付费/商业库(Wind/Choice/CEIC/EPS/CNKI)。
- 不追真真空指标(收入中位数、支出法 GDP、地市级债务分项、分行业税收、区县 GDP)——**如实标注缺失,不估算、不编造**。
- 不引入 Playwright/JS 渲染环境(海关总署主站 412、人社部 JS 门控 → 本轮放弃,改走关区子站)。
- 不引入 OCR(全国统计年鉴 2015+ 为 JPG 扫描图、五经普年鉴为 JPG)——记为后续候选,本轮不做。

## 3. 设计原则

| # | 原则 | 含义 |
|---|---|---|
| P1 | **错 > 缺** | 宁可返回缺失并标 `verify`,绝不填入可能错的值(用户已定) |
| P2 | **禁止硬编码定位** | 表号、文件名、URL 一律从 TOC/详情页动态解析。实测证据:年鉴表号会**位移**(「国民经济主要年份主要指标」2016-2023 为 `0103`、**2024 为 `0102`**),文件形态隔年变异(`.htm` → `NNNN_T-T.html`),公报分页为**反序** `index_N` |
| P3 | **新增而非重构** | 现有 discovery→fetch→extract→store 管线保留;新源以适配器接入 |
| P4 | **口径与来源可溯** | 每行数据必须能回答「哪个源、哪一卷、哪个口径、原文在哪」 |
| P5 | **独立口径才算交叉验证** | 同源搬运(CNKI/EPS/年鉴/统计局 API 之间)**不构成**独立第二数据点 |
| P6 | **失败必带原因** | 任何源失败返回明确 message,不静默跳过、不静默降级 |

## 4. 架构:统一数据源适配契约

借鉴 `PKUJohnson/OpenData` 的 `df, msg` 范式,为「解放单一来源」立骨架。

```
app/fetch/
  base.py            # 新增:SourceAdapter 抽象 + FetchResult
  bulletins.py       # 轨A:公报(栏目页 + 分页遍历)
  yearbook.py        # 轨A:年鉴(TOC 按标题解析)
  nbs_api.py         # 轨C:国家统计局新版 API
  celma.py           # 轨C:CELMA 地方政府债券 API
  customs.py         # 轨C:厦门海关本关统计
  documents.py       # 既有(M5 注册表驱动),保留
```

```python
@dataclass
class FetchRecord:
    region: str; year: str; indicator_name: str; value: str
    unit: str = ""; category: str = ""
    raw_text: str = ""            # P4:原文溯源
    caliber: str = "final"        # 既有维度
    source_kind: str = ""         # bulletin|yearbook|api|thirdparty
    source_rank: int = 1          # 1=主源(统计局) 2=年鉴 3=异源
    source_url: str = ""

@dataclass
class FetchResult:
    records: list[FetchRecord]
    message: str = ""             # P6:失败/空结果必须说明原因
    ok: bool = True

class SourceAdapter(Protocol):
    kind: str
    def fetch(self, cfg: dict, client) -> FetchResult: ...
```

`orchestrator` 与 `quanzhou.py` 按 `kind` 分派,不改各自的既有流程。

## 5. 数据模型变更

### 5.1 迁移(幂等,沿用 `_migrate` 模式)

| 表 | 新增列 | 用途 |
|---|---|---|
| `pages` | `source_kind TEXT` | 区分 bulletin/yearbook/api/thirdparty |
| `pages` | `edition TEXT` | 年鉴卷年(与数据年不同:年鉴 2024 卷载 2023 年数据) |
| `data_values` | `source_kind TEXT` | 冗余便于查询与排序 |
| `data_values` | `source_rank INTEGER DEFAULT 1` | **主源优先排序** |

### 5.2 **关键风险与对策:分析层唯一性**

**风险**:现有分析层假定 `(region, year, indicator_name, caliber)` 唯一。引入多源后同一三元组会出现**多行**(如泉州 2024 GDP 同时来自公报与年鉴),若不加隔离,**所有既有分析会静默错乱**。

**对策**:建视图 `data_values_primary`,按「`source_rank` 最小 → `extracted_at` 最新」取唯一行:

```sql
CREATE VIEW IF NOT EXISTS data_values_primary AS
SELECT * FROM data_values dv
WHERE dv.id = (
  SELECT id FROM data_values x
  WHERE x.region = dv.region AND x.year = dv.year
    AND x.indicator_name = dv.indicator_name AND x.caliber = dv.caliber
  ORDER BY x.source_rank ASC, x.extracted_at DESC, x.id DESC LIMIT 1
);
```

- **分析层全部改读视图**(`repository.query_data` 增加 `primary_only=True` 默认)。
- 原始对照:新增参数 `include_alt=True` 才返回全部来源 —— 供交叉验证与审计使用。

### 5.3 新表

```sql
CREATE TABLE IF NOT EXISTS cross_checks (
  id INTEGER PRIMARY KEY,
  region TEXT, year TEXT, indicator_name TEXT,
  source_a TEXT, value_a TEXT,
  source_b TEXT, value_b TEXT,
  diff_pct REAL, verdict TEXT,        -- agree|diverge|single_source|not_comparable
  note TEXT, checked_at TEXT
);
```

`regions`(adcode 行政区划维表)列为 **P2 可选**,不在本轮引入,理由见 §9。

## 6. 四轨详细设计

### 轨 A · 时间深度(最高性价比,先行)

**A1 站点适配知识库** — 新建 `config/site_adapters.yaml`

```yaml
adapters:
  - region: 泉州市
    bulletin_column: http://tjj.quanzhou.gov.cn/tjzl/tjgb/
    paging: { pattern: "index_{n}.htm", start: 1, max_pages: 8, stop_on_no_new: true }
    detail_link: "t20\\d{6}_\\d+\\.(htm|html)"
    encoding: auto
    verify_tls: true
  - region: 厦门市
    bulletin_column: https://tjj.xm.gov.cn/tjzl/ndgb/
    referer: https://tjj.xm.gov.cn/      # 实测栏目页直连 403,需 Referer
  - region: 三明市
    verify_tls: false                    # 实测 SSL 握手失败
  - region: 漳州市
    note: "tjj.zhangzhou.gov.cn 实测 ConnectionReset,走 manual listing_urls"
```

收集项:栏目 URL、分页模式、详情链接正则、编码、`verify_tls`、`referer`。无适配器时回退现有启发式(**保持向后兼容**)。

**A2 分页遍历** — `bulletins.py`

- 支持三种分页形态:反序 `index_{n}.htm`(泉州实测)、顺序 `index_{n}.htm`、无分页(福建省级一页到底,70 个详情链接)。
- 终止条件:无新详情链接 / 达 `max_pages` / 全部详情页已入库(P2 的 `content_hash` 去重已具备)。
- **P2**:详情链接一律从当前页 HTML 解析,不拼 URL。

**A3 年度区间目标** — 采集从「最近一期」变为「年度区间」

- CLI/config 新增 `year_range: 2015-2025`;`_derive_year` 结果落在区间外则记日志并跳过(避免"来者不拒")。
- 目标态:泉州公报候选从 1 → 19 年。

**A4 泉州年鉴采集器** — `yearbook.py`,**本轮技术难点**

实测到的**四种形态必须同时兼容**(夹具回归的基线):

| 卷年 | TOC URL | 表文件形态 |
|---|---|---|
| 2016 / 2020 | `…/qztjnj<年>/contents-cn.htm` | `./cn/html/0103.htm` |
| 2023 | 同上 | `./cn/html/0103.htm`(**标题已含「主要年份」**) |
| 2024 | 同上 | `./cn/html/0102.htm`(**表号位移**) |
| 2025 | 同上(210 个 href) | `./cn/html/0102_1-3.html`(**扩展名 + 命名双变异**),另有 `00a.htm`/`01a.htm` 导航页、`####_sheet#.html` |

**解析策略(遵守 P2)**:
1. 取 TOC → 解析 `<a>` 的 **(href, 标题)** 对,标题归一化(去序号前缀、全角 `—` → `-`、去空格)。
2. 目标表**按标题模糊匹配**,不按表号:`国民经济.*主要年份主要指标`、`财政.*收支`、`对外经贸`、`人民生活`、`物价`。
3. 命中多个候选时**全部抓取**并在抽取层靠 `_converge_values` 收敛(已有能力),而非猜一个。
4. 表文件加载后交给**既有** `app/parse/series_table.py`(已实现 lxml colspan/rowspan 矩形展开)—— 这是复用而非重写。
5. 2015 卷为 24 MB PDF:`pdfplumber` 文本层可试;若为扫描版则按 P1 **标记缺失**,本轮不做 OCR。

**A5 修复两个既有 bug**(证据见 `EVIDENCE_DATA_GAP.md` §8)
- `_find_bulletin_links` 关键词误匹配:`执法证公示` 被标为 bulletin → 加了 `and not any(k in text for k in ("公示","执法","通知","证件"))`。**注意:不得排除「普查」** —— 经济普查公报是有效数据源。
- 栏目页自身被当正文入库(福建省 `/xxgk/tjgb/`):入库前判断「同域详情链接数 ≥ N」则判定为列表页,继续下钻而不入库。

### 轨 D · 交叉验证(抗数据美化)

**核心洞察(来自实测反例)**:「多源」≠「独立」。CNKI / EPS / 中经网 / 年鉴 / 统计局 API **彼此同源搬运**;企查查 / 天眼查 / 爱企查 / 启信宝彼此同源(均回灌 gsxt),**只算 1 个信号**。把它们当独立验证会制造虚假置信。

**独立口径强度排序**(据实测):
`VIIRS 夜光` > `中电联用电量` > `巨潮 cninfo 年报(经审计,企业法人口径)` > `厦门海关` > `外汇局福建分局` > `税务`

**本轮落地组合**(均实测可达):

| 指标 | 主源 | 独立第二源 | 落地 |
|---|---|---|---|
| 泉州进出口 | 公报/年鉴 | **厦门海关分市表** | 轨 C `customs.py` |
| 福建省 GDP / 一般公共预算收入 | 年鉴/公报 | **CELMA `zb=1201` / `1101`** | 轨 C `celma.py` |
| 福建省政府债务 | 预决算报告 | **CELMA `060101`/`060102`** | 轨 C `celma.py` |
| 泉州人口 | 公报/年鉴 | 七人普 + 福建年鉴 `0301` | 轨 A/B |

**判定规则**:`|diff_pct| ≤ 3%` → `agree`;`> 3%` → `diverge`(升级为报告显性提示,并列出双方 `raw_text`);仅一方有值 → `single_source`(**不给定论**,符合 P1)。

**输出**:`cross_checks` 表 + 决策树新增 `T5` 层「跨源一致性」节点 + Kami 报告新增章节。

### 轨 E · 地方债务专题(用户指定加权,2026-09-14 追加)

**加权理由**:用户明确关注地方债务;且证据显示**地市级债务是「有源未挖」而非真空** —— `ALT_SOURCES.md` 判定「地市级债务分项拿不到」指的是**部委渠道**;而我们的既有采集里,**泉州市本级预算报告已含债务余额与限额**(M6 已入库:2024 年余额 2661.16 / 限额 2753.80 亿元)。地方预决算报告是地市级债务的**法定披露渠道**。

**E1 数据源(两级并用)**

| 层级 | 源 | 内容 | 实测状态 |
|---|---|---|---|
| 省级 | CELMA 地方政府债券信息公开平台 `governbond.org.cn:4443/api/loadBondData.action` | 一般债余额 `zb=060101`、专项债余额 `060102`、限额 `010101/010102`;年 2015-2025 + 月 2018-01 起 | 200 / 43013 B,**无鉴权** |
| 地市级 | **地方预决算报告**(泉州/福建历年预算 + 决算报告) | 债务余额(预计执行数)、中央核定限额、新增限额、还本付息 | 既有源已含,**需按年回溯扩充** |

⚠️ CELMA 的 `12xx` 社会经济序列实测异常(福建进出口 2015=1688.5 → 2016=10345.4),**仅用 `01/03/04/05/06/07` 债务类**。
⚠️ 需专项侦察:福建省财政厅债务信息公开专栏、泉州市财政局历年预决算归档深度。

**E2 数据模型**:复用 `econ_series`(`data_type='debt'`),规范指标名:
`债务余额`、`债务限额`、`新增限额`、`一般债务余额`、`专项债务余额`、`还本付息额`。
`caliber` 区分 **决算(final)** 与 **预算(budget)** —— 既有口径隔离机制直接复用。

**E3 分析模块 `app/analysis/debt.py`**(延续 M8 原理标注风格 P1-P6)

| 指标 | 公式 | 阈值与含义 |
|---|---|---|
| 限额利用率 | 债务余额 / 债务限额 | > 90% 新增空间受限(既有 T3-4 已用) |
| 债务率 | 债务余额 / 综合财力(一般公共预算收入 + 政府性基金收入 + 上级补助) | 分档标注,参考警戒区间 |
| 债务/GDP | 债务余额 / 同年 GDP | **强制同年口径**(沿用 A10 修复的纪律) |
| 新增债务投资转化率 | Δ债务 / Δ固定资产投资 | 下降 → 举债拉动效率衰减 |
| 一般债/专项债结构 | 专项债 / 债务余额 | 专项债占比过高 → 与土地/项目收益绑定风险 |
| 到期与付息压力 | 还本付息 / 综合财力 | 流动性压力 |

**E4 决策树债务节点扩充**:T3 层由 1 个节点扩至 **5 个**

- `T3-4` 限额利用率(既有,保留)
- `T3-6` 债务率是否越过警戒区间(**新增**)
- `T3-7` 一般债/专项债结构是否失衡(**新增**)
- `T3-8` 新增债务的投资转化效率是否衰减(**新增**)
- `T3-9` 土地依赖 × 债务到期的联动风险(**新增**,复用既有土地依赖指标)

**E5 报告债务专章**:Kami Parchment 风格独立章节(债务规模、结构、空间、效率、风险、跨源对账)。

**E6 交叉验证**:地方预决算报告披露值(地市级) ↔ CELMA(省级) 对账;省级口径差异进 `cross_checks`。

## 7. 实测硬约束清单(实现时必须遵守)

1. **年鉴表号会位移** —— 2016/2020/2023 = `0103`,**2024 = `0102`**。→ 按标题匹配。
2. **年鉴文件形态隔年变异** —— `.htm` → `NNNN_T-T.html`,且 `sheet`/`Sheet` 大小写混用。→ 从 TOC 解析。
3. **年鉴标题在演化** —— 「国民经济主要指标」→「国民经济主要年份主要指标」;破折号 `1-3` → `1—3`。→ 标题归一化后再匹配。
4. **公报分页是反序的** —— `/tjzl/tjgb/` 是第 1 页,`index_1.htm` 是第 2 页。
5. **年鉴卷年 ≠ 数据年** —— 2024 卷载 2023 年数据;`edition` 与 `year` 必须分开存。
6. **站点可达性各异** —— 厦门栏目页 403(需 Referer)、三明 SSL 失败(需 `verify_tls: false`)、漳州 ConnectionReset、南平首页无公报入口、国家统计局首页无公报入口。
7. **`Invoke-WebRequest` 不能作可达性判据** —— 其 TLS 指纹被部分政府站 WAF 拦(403),而 `curl.exe -4` 同 URL 为 200。
8. **旧 `easyquery.htm` 已封禁** —— 403 `reason:UrlACL`,勿再投入。

## 10. 风险与回滚

| 风险 | 等级 | 对策 |
|---|---|---|
| 年鉴格式继续漂移 | 高 | 标题匹配 + 四卷夹具;新增卷年只需补夹具 |

| 官方 API 反爬升级 | 中 | 适配器失败即 `message` 上报,不阻断其他源;旧公报路径始终可用 |
| 厦门海关历史深度不足 | 中 | 先探明再决定;不足则仅作近期校验 |
